Alert settings

How alerts work

  • New access point: the device remembers every access point it has ever seen, also across restarts. The first scan after setup or a factory reset only learns what is already around; after that only really new access points raise an alert (at most 5 per scan).
  • Open network and very strong AP are checked when a new access point appears.
  • High density fires when a channel reaches the limit, and again only after it has dropped below it.
  • System: WiFi outages longer than 30 s (reported after reconnecting), the MQTT broker down for more than a minute, free memory below 6 KB, and restarts caused by the watchdog or a crash. Three such restarts in a row raise a restart-loop alert.
  • The last 24 alerts are kept, also across restarts. A factory reset clears them.

Where alerts go

  • This page, plus a pop-up on any page of this interface while it is open.
  • MQTT topic …/alerts. In Home Assistant this is the Alert event entity, with one event type per alert type (new_ap, open_ap, strong_ap, channel_density, ...).
  • The Home Assistant Alert binary sensor is on while there are unread warnings or critical alerts. The Mark alerts as read button in Home Assistant clears it, like the button on this page.

BLE settings

How BLE is used

Home Assistant over Bluetooth (BTHome)

  1. Home Assistant needs Bluetooth near the device: a Bluetooth adapter on the Home Assistant machine, or an ESPHome Bluetooth proxy.
  2. With BTHome advertising on, Home Assistant discovers a new BTHome device by itself (Settings → Devices & services). No pairing and no MQTT needed.
  3. Its sensors: Count = WiFi access points detected, Count 2 = BLE devices nearby, Count 3 = recommended WiFi channel (0 until the first scan). Rename them in Home Assistant.

MQTT keeps working in parallel and remains the complete integration; BTHome is a small, cable-free extra.

GATT service (any BLE app)

  • Service 6e5a0001-7a1d-4c3b-9f2e-0e5f5a57a001
  • Characteristic 6e5a0002-7a1d-4c3b-9f2e-0e5f5a57a001 (read / notify): a JSON summary, e.g. {"aps":12,"open":1,"channels":5,"strongest":-34,"recommended":11,"ble":9}
  • Try it with nRF Connect on a phone: connect to the device name above and read the characteristic.

Good to know

  • WiFi and BLE share one radio. Scans take turns: a BLE scan (5 s, passive) never runs during a WiFi scan.
  • Changing the name or switching BLE on/off takes effect after a reboot.
  • The scan only listens (passive). It does not connect to other devices.

Connecting to Home Assistant

  1. MQTT broker. In Home Assistant open Settings → Add-ons → Add-on store, install Mosquitto broker and start it. Skip this step if you already run a broker.
  2. User for this device. Settings → People → Users → Add user (turn on Advanced mode in your profile if the Users tab is missing), e.g. wifimonitor with a password. The Mosquitto add-on accepts Home Assistant users.
  3. MQTT integration. Settings → Devices & services: Home Assistant usually offers MQTT as discovered, so click Configure → Submit. Otherwise use Add integration → MQTT.
  4. This page. Turn on Enable MQTT. Set Broker to the IP address of Home Assistant (or of your broker), Port 1883, and the user name and password from step 2. Keep MQTT discovery on with prefix homeassistant, then press Save.
  5. Check. MQTT status should show connected. In Home Assistant open Settings → Devices & services → MQTT → Devices → wifi-monitor-01. You will see the sensors, the Scan now button and the New access point event.

If it does not connect

  • bad username/password: check the user from step 2, or the logins in the Mosquitto add-on.
  • broker unreachable: wrong IP or port, the broker is not running, or a firewall blocks port 1883.
  • Connected but no device in Home Assistant: the discovery prefix must match the MQTT integration settings (default homeassistant).

    How to update
    
      
    Firmware
    
      
      
        
    1. Build it on the PC: pio run. The file is
          .pio/build/nodemcuv2/firmware.bin.
      2. 
        
    2. Choose the file above. The page reads its version and board before anything is sent, and refuses
          files that are not ESP WiFi Monitor firmware for this board.
      3. 
        
    3. Press Upload and install. The device writes the new firmware next to the running one, checks
          it, and restarts (about 30 seconds). Settings, history and alerts are kept.
      4. 
      
    
      
    Web interface files
    
      
      
        
    1. Choose the data folder of the project and press Upload files.
      2. 
        
    2. When it is done, reload the page to use the new files.
      3. 
      
    
      
    If a release changes both, update the firmware first, then the web files.
    
      
    If something goes wrong
    
      
      
        
    • A failed or interrupted upload is never activated; the device keeps running the old firmware.
      • 
        
    • Scans pause while an update is being uploaded.
      • 
        
    • As a last resort, flash over USB: pio run -t upload.
      • 
      
    
      
    Updates are not password protected. This device is meant for a trusted local network
        only; never expose it to the internet.

    Maintenance
    
      
    
        
        
      
    
      
    
        
        
        
      
    
      
    Factory reset prepares the device for a new owner. It erases the WiFi network, the MQTT
        broker and credentials, all other settings and the history, and removes the device from Home Assistant
        (if MQTT is connected). The device then restarts as the setup hotspot. Firmware and web files are kept.
    
    
    
   
    
   
    
    
    
      
    About these settings
    
      
    Device
    
      
      
        
    • Device name: shown in the header and used as the device name in Home Assistant.
      • 
        
    • Hostname: the local network name. With the default you can open
          http://wifi-monitor.local (works on Windows, macOS and iOS; Android usually needs the IP
          address). Lowercase letters, digits and - only. Takes effect after a reboot.
      • 
        
    • Timezone: a POSIX TZ string used for the clock and history timestamps. Takes effect after a
          reboot. Examples:
          
        
            
      • Central Europe (Belgrade, Berlin, Paris): CET-1CEST,M3.5.0,M10.5.0/3
        • 
            
      • Eastern Europe (Athens, Sofia): EET-2EEST,M3.5.0/3,M10.5.0/4
        • 
            
      • UK / Ireland / Portugal: GMT0BST,M3.5.0/1,M10.5.0
        • 
            
      • US Eastern: EST5EDT,M3.2.0,M11.1.0
        • 
            
      • UTC: UTC0
        • 
          
      
        
      • 
        
    • The WiFi network is changed on the WiFi page, which
          lists the networks the device can see.
      • 
      
    
      
    Network
    
      
      
        
    • Static IP: the device always uses the same address. Pick an address outside your router's
          DHCP range (or reserve it in the router). Takes effect after a reboot.
      • 
        
    • If the address is wrong, the device is unreachable. Recover it by holding the FLASH button for
          10 seconds (factory reset), or with the serial console.
      • 
        
    • Choosing a different network on the WiFi page switches back to DHCP automatically.
      • 
      
    
      
    Scanner
    
      
      
        
    • Scan interval: how often the device scans. A scan takes about 2 seconds and briefly moves
          the radio off your network's channel, so very short intervals make the web page and MQTT a little
          slower. 30 s is a good default; the minimum is 10 s.
      • 
        
    • Scan channels: All channels is normal. Scanning a single channel is much faster
          (about 0.1 s) and is useful to watch one channel closely; charts and analysis then only contain that
          channel.
      • 
        
    • Automatic periodic scan: when off, the device scans only when you press Scan now
          (web page or Home Assistant button).
      • 
        
    • Max tracked APs: how many access points the device remembers. Each one uses RAM, so values
          above 100 leave less memory for the web server and MQTT; check Free heap on the
          System page. Takes effect after a reboot.
      • 
      
    
      
    History
    
      
      
        
    • History retention: how long 5-minute summaries are kept in the device's flash memory. Older
          data is deleted automatically. The Live view on the History page is always the last 60 scans.
      • 
        
    • Stored history needs the correct time, which the device gets from the internet (NTP). Without
          internet access only the Live view has data.
      • 
        
    • For long-term history, use Home Assistant: its MQTT sensors are recorded like any other sensor.
      • 
      
    
      
    Appearance
    
      
      
        
    • Default theme applies to browsers where nobody has used the ◐ button yet. The button choice is
          remembered per browser.
      • 
        
    • Accent color: buttons, links and the selected menu item.
      • 
      
    
      
    Maintenance
    
      
      
        
    • Reboot: restarts the device. Settings and history are kept.
      • 
        
    • Backup downloads all settings as a JSON file. Passwords and the WiFi network are not included;
          after Restore on another device, pick its network on the WiFi page and enter the MQTT password
          again.
      • 
        
    • The FLASH button on the board: hold it for 10 seconds while the device is running for a factory
          reset. The blue LED starts blinking after 3 seconds as a warning.
      • 
        
    • Factory reset: use it before giving the device to someone else. Afterwards they connect
          to the ESP-WIFI-MONITOR-xxxx hotspot with a phone, the setup page opens by itself, and
          they pick their own WiFi network.
